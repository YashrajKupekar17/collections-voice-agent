YK Finance Agent Architecture

A voice agent that calls borrowers about missed EMIs, records promises to pay and hands hard cases to humans, without breaking RBI or US collection rules.

Is it decided?

Decided for v1 fixed

  • Three process types from one codebase
  • Cascaded pipeline: STT → LLM → TTS
  • Pipecat, Temporal, Postgres, no Redis
  • Where each piece of state lives
  • Compliance fails closed, runs in-process
  • Timeouts, retries and idempotency per call

Provisional measured later

  • Which STT, LLM and TTS: chosen by evals and P4 latency
  • Workflow details: designed in P7
  • Memory and RAG design: P8 and P9
  • Indian telephony: documented, not built
  • Hosting: local now, one VM later

One call, end to end

  1. The loan system reports a failed EMI. The API saves it and starts a workflow for that account.
  2. The workflow picks a time, rechecks payment, and runs the compliance gate: calling hours, stop flags, contact limits.
  3. It writes the attempt row, then asks the telephony provider to dial.
  4. When the borrower answers, the provider streams the audio to a voice worker. A pre-recorded greeting plays at once.
  5. Each turn runs STT → LLM → TTS. Tools such as verify_identity and create_promise enforce the rules in code.
  6. A promise is saved to Postgres before the agent says “confirmed”. The SMS with the payment link goes to the outbox.
  7. After the call, the workflow updates the case state, sends the SMS, and sets a timer to check whether the promise was kept.

Three timing paths

PathBudgetWhat runs there
Before the callsecondsPick accounts, compliance gate, load account and memory, warm connections
In the turn~800 msSTT, LLM, TTS, millisecond tools; save the promise and stop flags right away
After the callseconds to daysSMS and payment link, summary and memory, case state, promise check

When something fails

FailureWhat happens
Voice worker crashesOnly its live calls drop. The workflow records SYSTEM_FAILURE and retries later.
Workflow workers downNo new dials. Live calls continue. Temporal resumes every workflow where it stopped.
LLM slow or downAgent says “one moment”, retries on a backup provider, then ends politely and schedules a callback.
Dial request times outNo immediate redial. Check what happened first; the normal retry policy calls later.
SMS provider downRetries with backoff, then a dead-letter queue, an alert, and WhatsApp or a human.
Postgres downNo calls (compliance fails closed). A promise that cannot be saved is not confirmed.

Decisions behind it

  • D-003 Compliance fails closed; its data lives apart
  • D-004 Identity check in code, never read out
  • D-005 Promise rules enforced in a tool
  • D-006 Stricter US rule set for everyone
  • D-007 Eval simulator kept consistent by scripts
  • D-008 Three process types, no Redis
  • D-009 Pipecat for voice
  • D-010 Cascaded pipeline, not speech-to-speech
  • D-011 Demo telephony on Twilio
  • D-012 Models chosen by evals
  • D-013 Local first, one VM later
